# 历史背景图

为阅读页面制作可复用的背景素材。统一的是克制的色彩、构图留白和阅读舒适度；媒介、建筑、服饰及视觉语言随题材的时代、地域变化。不要把所有时代都画成古代水墨。

## 先判断用户正在做什么

| 用户意图 | 执行到哪里 |
| --- | --- |
| 讨论风格、推荐配图位置、整理提示词 | 提供建议与可审阅的提示词，不调用图像生成 |
| 明确要求“生成这一张”或选定的一组图 | 按该题材与数量生成候选图，展示预览并归档为 draft |
| 提供已有图片、要求上传/归档 | 保留原图和实际来源，登记候选；不重新生成 |
| 要求查看、查找、复用已有图片 | 先检索图库并打开原图，给出准确素材 ID 和文件位置 |
| 看过具体图后明确要求保存到某个背景位置 | 经目标应用已有的人工保存接口保存该版本与位置；没有对应接口时报告尚未接通，不用改 JSON、复制到 public 或部署来冒充启用 |

自动发现本技能只允许执行与当前请求相符的工作。滚动阅读、打开页面、导入史料、发现缺图、配图建议都不构成生成授权。用户要求生成不等于要求启用；用户已对具体版本和位置确认保存时，也不要重复索要同一确认。

图片仅用于页面背景。未确认的候选图不进入公开展示；保存后仅在人工指定的范围生效，重新生成的候选不替换正在使用的版本。

## 制作候选

1. 从现有上下文确定题材、时代、地域、用途和文字所在区域。缺少细节时给出合理设计假设；年代、服饰或建筑不确定的部分用意象表达，不捏造史实依据。配图位置可以建议事件发生段或主要人物叙述段；拿不到真实定位信息时记为建议，不编造绑定 ID。
2. 阅读 [art-direction.md](references/art-direction.md)，选取合适的媒介和淡彩。赤壁、人物水墨只是示例；按实际时代重新组织视觉语言。
3. 使用该文的提示词框架，保留最终完整提示词。约定画面比例、主体落点和文字留白；不把 UI 文案、日期或标签烧进图片。
4. 仅在用户已明确触发生成时调用当前可用的图像生成工具。环境提供 `imagegen` 技能时先遵循其工具工作流，默认使用内置生成能力。内置能力不可用时，保留提示词并说明限制；CLI/API 回退需要用户明确选择及本地 `OPENAI_API_KEY`，不能静默换工具或模型。不要把手绘 SVG、渐变或测试图片当作生成结果。
5. 实际检查图像的题材、时代线索、构图、色彩及文字区干扰。需要改图时指出具体变化；不要自行扩大生成数量或不断自动重试。用页面预览检查可读性，原图仍保留可复用的层次。
6. 把真正生成或用户提供的原图、实际提示词和元数据归档为未启用候选。使用 [library.md](references/library.md) 的脚本；不会调用模型、启用背景或发布网站。生成工具的临时文件路径不能成为项目的永久引用。

## 归档与复用

仓库默认素材位置是 `apps/chronicle/assets/backgrounds/`，技能本身保存在 `.agents/skills/historical-background-art/`。其他项目传入自己的 `--library` 路径即可，不要求 Chronicle 目录结构。图片、提示词和清单纳入版本管理前检查是否属于当前用户允许提交的素材；不提交凭据或私有参考文件。

按题材、时代、画风、标签检索，使用 `show` 验证并取得路径，再用图像查看工具打开原图。复用时保留已有素材身份；变更图像或提示词产生新候选，可用 `derived_from` 关联旧候选。用相同提示词再次生成不保证得到相同像素，精确复用依赖原图和 hash。

Chronicle 的人工上传、预览、保存并显示及位置关联设计见仓库的 `apps/chronicle/docs/background-art.md`。本地候选库是创作档案，不是后台上传服务或公开素材目录；技能不能授予自己发布权限。

交付时说明：实际完成的是建议、候选还是已保存关联；给出图片/提示词/清单路径及素材 ID；说明使用的生成方式或上传来源。没有真实生成、人工保存或页面接线证据时，不声称图片已经在阅读页显示。
