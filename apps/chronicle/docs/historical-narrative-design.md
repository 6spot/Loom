# Chronicle 连续历史叙事与阅读页面

主阅读体验是**综合多份资料形成的正序历史叙事**。书籍提供原文与依据，不决定
前台阅读组织。首页的重要时期、事件和搜索帮助读者选择起点；到达后，继续
向下阅读相邻历史。本文记录产品职责；数据与生产规则由
[source-corroboration.md](source-corroboration.md) 统一定义。

## 正式页面

| 页面 | 职责 |
| --- | --- |
| `/` | 少量经过审核的重要时期、事件入口与搜索 |
| `/history` | 固定版本的连续综合正文，时间轴和当时人物地点跟随阅读位置 |
| 事件词预览 | 轻量介绍与主动定位；悬浮本身不跳转、不改阅读位置 |
| 阅读资料 | 具体结论、明确性理由、各方原文、引用归属与完整章节 |
| `/read`、`/chapters` | 按需核查来源的原书译文，保持来源版本语义 |
| `/entities/{id}` | 现有对象资料和事件轨迹；完整人物生平阅读由 R3 交付 |

页面使用中性的纸色、墨色与克制的点缀色，适配不同历史时期。正文保持视觉
中心；不在段落间插入大事件卡、锚点提示横幅或固定的“前情／发生／后续”栏目。
资料与技术记录不占据正常阅读的主体。

## 阅读页三栏

- **左侧：时间定位。** 两级导航以年份、有据范围或时期为区间，下级展示月份等
  细分时间和经过选择的关键发展。内容少时展开全部，长列表默认展开当前及邻近
  区间，保留用户主动展开/收起的选择。区间按钮只展开，节点才定位正文。当前
  节点离开轴内可见区时只滚动轴内部；用户手动浏览轴时暂停跟随，并可回到当前。
  重要入口与普通进展区分字重/节点形状，避免逐段堆成目录。传统月日保留原述；
  不明确的日期不强补公历年月，不把一处九月记载用于整场战事。
- **中间：正文。** 自然段连续排开，文字片段只关联自己支持的结论。下滚预读
  相邻内容，读完某一事件继续后文；到达当前发布范围末尾才停止。
- **右侧上方：附近的重要入口。** 标明当前读到的发展及附近可跳转的事件，
  随正文位置更新。它是定位工具，不把阅读范围变成事件筛选结果。
- **右侧下方：当时人物与地点。** 默认显示主要对象，每个对象独占一行，展示
  官职、爵号、效力、行政归属或实际控制。“率军南下”等行为留给正文和详情。
  没有依据的状态如实缺省，不能靠参与事件推定。按重要性筛选后没有内容的栏目
  整体隐藏；次要对象从统一的更多入口展开。内部 phase ID 不显示给读者。

窄屏以单栏正文为主，时间轴、此时此地和阅读资料通过独立面板展开。面板支持
键盘、Escape、焦点返回和减少动画设置。离开阅读去看人物，再返回时恢复同一
版本、段落和段内位置。

## 细节、阶段和锚点是三种粒度

**前台锚点不是抽取事件清单。** 生产稿通常选择 1–5 个重要时期或完整发展事件，
每个入口需要说明选择理由，编辑在正文审核时增删。其数量不随 Claim、Event
或段落数量自动增长。

“刘备领有徐州”“周峻之子未被任用”“刘备即汉中王”等事实可以留在正文、
对象经历及原文检索中，不能只因为被抽取成事件就各占一个首页或侧栏入口。
“取得益州”是否独立导航，要看当前叙事范围与它覆盖的发展过程，也不能
仅凭标题机械排除或全收。原始资料不因减少入口而删除或强行归并。

内部阶段必须足够准确。例如进入益州、成都出降、此后领益州牧可以处于不同
阶段，避免刘备刚入蜀就显示他已控制益州。这些阶段可以共享一个大事件入口。
任免、爵号和控制权变化不必各自变成阅读入口。

## 明确与存疑

每条结论独立记录 `clear` 或 `uncertain` 与理由。正常墨色对应允许直接这样
表述的事实或有归属的转述；存疑文字稍弱，但保持可读对比度。状态项同时用
实心／空心标记和文字，不能只靠颜色区别，也不能把整个人物一起变灰。

原文确有一句话不代表它证明所有附加结论。“曹操在信中称自己焚船”与“曹操
确实主动焚船导致退军”须区别处理。单一来源可以支持有限的明确陈述，同书
多传不自动成为多个独立见证。依据按需深入查看，不在正文旁默认铺开。

## 生产和首版边界

完整章节先走既有翻译、联合抽取、身份核对与来源发布。Studio 中显式选择
已发布完整章，再执行事实核对、第一次审核、综合叙事、第二次审核和发布。
公开页面只读取发布版本，不在浏览器中生成内容。

当前综合版本限于一组选定完整章，最多 256 个正文段落。阅读可以越过此版本
内部的时期和事件；**跨多个独立生产批次自动拼接全部历史尚未实现**。新一轮
生产形成新版本，旧链接仍读取旧正文和依据。不能用有限范围的分页测试宣称
无限规模历史已经完成。

背景插图的产品规则保持为：AI 可建议位置，人工主动生成或上传、核验并保存
后才显示。古代、近代、现代分别采用时代相称的画面，颜色均克制、文字优先。
本轮没有自动生成图片；新综合段落到背景资产的配置接线需独立实现和验收，
不得将原来源位置直接冒充新叙事位置。

## R3 人物页交接

人物页的三栏职责已确认：左侧是简短生平概况及时间定位，中间是个人经历的
连续正文，右侧是读到该阶段的身份、效力和关联对象。经历不会在三栏重复。

本轮提供固定正文版本、段落到阶段的映射、明确枚举适用阶段的状态结论及
原文依据。R3 扩展专门时态判断、完整人物生平生产与页面；不另建事实库，
不把筛选主历史段落直接称作完整传记。主历史进入人物时的可靠阶段对应、
未知对应处理和人物页往返分别验收。

本轮直接修改正式 React 页面和生产链，独立静态设计站不作为交付。当前要求
与验证记录在 [C2-R2E](../../../docs/tasks/chronicle/reading-enhancement/README.md)，
按仓库标准完成测试、review 和 PR，不增加 Task Ledger 状态对账步骤。
