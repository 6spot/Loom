# 分阶段章节生产（0.4）

本合同承接已确认的整章纯译文、独立提取和有界审核方案，拥有新生产版本
`chronicle.chapter-candidate / 0.4` 与 `chronicle.chapter-artifact / 0.4`。
它取代 [章节生产合同](chapter-production.md) 中新任务的联合调用、全部原注
翻译及联合纠错规则；0.1、0.2、0.3 的 schema 和历史产物解释保持冻结。
本合同仍位于 Amendment 0006 的 Chronicle 应用权限内，不改变 Amendment
0007 的跨来源身份人审、canonical 合并、负约束或 Loom 引擎权限。

## 输入及正文范围

自然章仍是一个完整 chunk。所有需要理解史料的模型请求都带完整章节，原文与
原注均保存；不按自然段独立调用翻译，不以摘要替换本章原文。

程序保存 `source_scope`，包括整个来源绑定、正文范围、原注范围及其精确 hash。
本版只自动识别资料中显式、配对的 `〈…〉` 原注标记，跨段和嵌套保持完整。
`〔…〕` 校订文字仍属于正文。无法确定的标记不静默吞掉内容：报明确的范围
错误，保留全部输入供整理。未加标记的注家续引必须在语料整理时补正或作为
完整正文保留，不能在程序里硬编码某本书某一段为注释。范围核对也是内容复核
的一项，机械配对不证明版本整理正确。

`source_scope` 是程序字段，不由模型重写。每个正文片段有固定句柄、原始 block
与章内相对 code-point 范围；加上 `chapter_start` 可定位整个 revision 中的绝对
范围。定位片段不构成独立翻译任务。原注可以为提取、判断和
按需溯源提供依据，但不单独译成读者正文。正文的主语、引述、传闻与不确定性
必须保留，不能为叙事通顺补造史实。

模型提示保留完整章，并在原文块及正文／原注片段旁直接提供对应的精确文本，
避免模型靠字符坐标推算编号。这些 `text` 仅为提示视图从章内坐标切出的字段，
不回写冻结 request、`source_scope` 或其 hash。引文必须逐字复制并绑定包含它的
原文块；不连续依据使用多条 selection，不用省略号拼成伪引文。完整提示仍受
同一个章节输入预算约束，超限明确失败，不截断来源。

## 固定步骤及保存

步骤属于既有八阶段中的 `extract`，不新增顶层队列或另一个生产入口。

1. **translation**：整章纯白话文本。模型不输出 JSON、引用编号、标题、注释
   或人物表。程序按自然段排版并分配稳定段落 ID，保存原始文本。
2. **extraction**：从完整原文独立提取已有 C0 Entity/Event/Claim、原文依据及
   R3 阶段事实；不要求重新输出译文。与 translation 无依赖，可以并行。
3. **comparison**：仅在某步骤有多个候选时调用，比较整个固定候选集，选择
   一个明确版本，保存各稿差异、采用理由和未决问题。不拼接投票产生“事实”。
4. **linking**：消费已选定的译文和提取版本，返回段落来源、实体/事件关联、
   阅读时间和阶段绑定，不输出或重写段落正文。组装为完整 0.4 候选后执行现有
   引用、日期、主体类型、阶段与覆盖校验。
5. **review**：核验完整章、当前候选、来源范围、全部候选/比较记录和历次意见
   的处置。每个报告必须绑定当前候选 hash 与所见历史 hash。
6. **repair**：存在可以修正的问题时，默认仅一轮局部补丁；针对固定对象及其
   原值 hash 修改，正文不得删除、重排或整章覆盖。产生新版本后重新校验，再
   执行一次 review。修改涉及关联时使受影响关联失效并重新生成。

每个 AI 步骤可配置一个或多个模型。单候选不增加无意义的比较调用；复核仍按
配置执行。多路比较若无法给出一致的、有依据的选择，进入人工例外；不递归
增加裁判模型。模型相互一致不是史料真实性证明。

传给模型的结构定义必须自包含：提取和关联所用的历史 schema 外部引用通过
既有离线 registry 收拢为本地定义，模型不需要访问仓库文件。提示、配置指纹
和实际校验使用同一份完整步骤 schema，不能只发送未展开的文件引用。
任务配置还保存实际提示模板的指纹；只改提示词、未改模型名或 schema 时，
也不能在同一任务的后续章节静默生效。

每次尝试立即追加到 `ingestion_outputs`，包括步骤/尝试编号、模型与请求配置、
上游版本、完整原始文本结果、解析结果、验证报告、完成状态、已知用量和耗时。
缺失用量为 null，不写成零。checkpoint 只引用已提交的输出。模型调用期间不
持有事务；提交时检查 owner 与实际未过期租约。子步骤不各自增加 chunk 的
attempt；整章接受或执行失败才追加原有 chunk run。

恢复按步骤输入和配置指纹复用已完成结果。输出、提示、模型或上游版本发生
变化时，不能沿用依赖它的意见/关联。保存成功但 checkpoint 未写入的输出也能
通过重验收养。已开始或失败的尝试保留，技术重试有固定预算，不作为“无异议”。
同一任务配置已冻结后不接受静默换模型；修改生产配置需明确创建新任务/版本。
translation、extraction、linking 或 repair 返回完整但校验无效时，在该节点
剩余的 `max_step_attempts` 预算内立即重试，附上此步的完整原始返回与具体错误；
不重译或重做其他成功步骤，也不
新开节点绕过预算。重试提示、所修结果 hash 与每次返回均保存。预算耗尽或
完整错误上下文超限时停止该步，不截断诊断、不接受部分结果。
review 和 comparison 的格式无效结果可能已包含实质异议，必须持久复用并进入
现有人工 gate；不能重新生成一份无异议报告来覆盖它。即使随后其他步骤失败、
恢复时预算已耗尽，也保留原意见。此策略随任务配置冻结。没有有效报告的纯
网络失败仍可在原预算内补调用，不当作已经获得一份意见。

## 接受与争议

完整返回、结构有效、内容接受和公开发布是不同状态。自动内容接受必须同时
满足：所有配置中的必要模型都完整返回、所有硬校验通过、每份复核绑定当前
版本、正文范围检查完整、所有旧问题都有明确处置、没有未解决的处理错误。
复核只能给出意见和结论，不能同时附补丁并批准。未知字段、过期版本、遗漏
意见、新问题或反转意见不能靠一句 `pass` 放行。

意见区分 `processing_error` 与 `source_uncertainty`。前者是错译、错主体、错
引用、错时间等处理问题；后者是史料自身不确定，必须以相应限定保存，不可
伪装成明确事实。官职事实只有一个实际持有者；亲属关系不能放入政治效力；
推荐、追赠、任命者、到访和地点控制不得相互替代。普通事实也不自动变成导航
锚点，精选入口仍由综合叙事合同拥有。

技术失败保留为 failed，操作员可以按已有 retry 恢复失败步骤。内容预算耗尽
或存在实质争议时，一章创建一个 `stage_gate / scope=chapter_content` 的
ReviewItem，保存候选 hash、完整意见集 hash、请求指纹、来源绑定及输出引用。
恢复只采纳该固定版本的决定，不重复创建 gate，也不额外打开 chunk_failure。
决定同时绑定具体保存的 draft 及意见历史；人工修订即使恢复成旧版文字，也
必须重新复核，不能仅凭正文 hash 相同重放旧修订或旧批准。

人工 `accept` 只能接受原样、校验通过的候选，必须逐项处置问题并说明理由；
请求不得包含补丁。`revise` 只保存局部修改，形成新版本并经过后续复核，不能
同时批准。同一修订可按提交顺序追加多条来源或事实记录；多条整记录删除按
原候选索引倒序执行，不能与同一数组内的编辑或追加混用。每条原值 hash 仍
基于修改前的固定候选校验，重叠编辑、重复删除及整集合替换继续拒绝。
`reject` 取消任务。决定按 job→review 的锁顺序提交，取消后、重复
提交、过期候选、过期意见集及遗漏问题均拒绝。来源原文、各模型候选和意见在
现有审核页展开，保存/下一项保持可达，不能在批准前要求先创建 accepted 章。

自动内容接受仅授予本章进入 assemble 的资格。它不替代跨章/跨来源身份决定、
R3 状态依据评估或显式综合叙事的来源选择与发布规则。后续仍通过既有
resolve→publish→present 原子发布链；网页只读完整已发布版本。新全局自动
身份或综合发布策略不在本次权限范围，不能借本章通过绕过其审核。

## 产物及验证

0.4 保留 0.3 的完整候选字段，并增加程序持有的 `source_scope`。基础引用、
日期、阅读、状态校验复用既有纯验证器；只有正文覆盖按明确的正文范围计算，
不以原注关联充当译文覆盖。0.4 artifact 额外绑定生产记录和内容接受凭据，
全部 candidate/artifact/unit/anchor hash 按实际版本重新计算，不能改版本号后
沿用旧 hash。旧产物不能冒充新的阶段结果，纯译文或提取单项不能单独发布。

回归至少覆盖：保存后恢复不重译、输出提交后崩溃可收养、配置漂移拒绝、旧租约
拒绝写回、多候选与少数意见全保留、缺复核结果不通过、改稿同时批准被拒、旧
审核不能批准新稿、局部修正不删正文、重复/反转意见不丢失、主体/日期/引用
无效被拒、人工 gate 可读/可处理、发布无半份结果。
真实失败样例来自 2026-09-12/13 的完整《先主传》试验；自动化验证不等于史料
正确性验收，不以本次实现关闭 #586 或 #549。运行配置和命令统一放在
[worker.md](worker.md)，审核 API/交互规则统一放在 [review-workflow.md](review-workflow.md)。
