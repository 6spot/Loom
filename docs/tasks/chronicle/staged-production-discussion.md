# 2026-09-12：整章纯译文、分阶段生产与可配置多模型

本页记录与用户确认的方向、试验边界和后续拆分依据。它不是新的生产合同，
也不表示后台已经实现。实际试验归档在
[分阶段试验报告](../../../apps/chronicle/corpus/second-round/acceptance/staged-production-20260912.md)，
关联 [#586](https://github.com/6spot/Loom/issues/586) 和草稿
[#681](https://github.com/6spot/Loom/pull/681)。任务状态继续由现用工具管理。

后续验证见 [纯译文、局部修正与恢复试验](../../../apps/chronicle/corpus/second-round/acceptance/staged-closure-20260913.md)。
整章纯文本请求已完成，但自动接受闭环未通过。此次发现的实施约束是：审核必须
携带完整前序意见与处置历史；通过只能绑定实际检查的版本；新补丁、新异议或
未解释的结论反转不能获得同一响应中的“通过”，超过修正预算进入人工例外。
试验文件检查点和离线 needs_review 判定不表示正式 worker/ReviewItem 已实现。

## 已明确的用户要求

1. 自然章是理解和翻译的基本单位。一次调用输入完整章节，只要求输出这章的
   连续白话译文。译文可以有自然段，不按段分别调用模型，不要求逐句对齐。
2. 翻译步骤最终采用纯文本输出。来源版本、模型、请求版本和 hash 由程序保存，
   不要求模型在翻译时同时填写人物、事件、来源编号或引用 JSON。
3. 阅读正文不夹入注释、模型解释、校勘和审核意见。原文、原注及引用保留在
   后台，用于理解、信息提取、复核和用户按需追溯。不显示注释不等于删除史料。
4. 每个阶段完成后保存结果，后续依赖固定的已保存版本。失败只重做受影响的
   阶段，不把已完成的整章译文再生成一遍。无依赖的任务允许并行。
5. 每个需要 AI 的步骤都可配置一个或多个执行模型。各模型独立执行，原始
   候选全部留存，再由可配置的 AI 对比、汇总；不是只给一个特定节点硬编码双模型。
6. AI 先处理能够依据原文解决的问题。通过发布条件的完整结果自动流转、发布；
   有无法解决的实质异议时才引入人工，不要求人工重新阅读所有无争议内容。
7. 默认继续尝试 Luna。多模型会增加调用和用量，按节点需要配置；不默认在所有
   字段、所有步骤反复调用多个模型。程序能完成的定位、版本检查和保存不调用 AI。
8. 用户产品仍是多份史料综合而来的连续历史流。史书是来源；整章译文是来源
   处理产物，不能把它直接改名成按历史时间组织的综合正文。

## 两种拆分必须区分

**工作职责拆分**是本次优先采用的方式：翻译、提取、复核、汇总分别执行，
每步仍能看到其所需的完整章节。纯译文的自然段是排版，不是独立模型任务。

只有完整章的单一职责请求仍不能完成时，才讨论**章内容量拆分**。不能因旧的
联合输出失败，就直接把正文切成若干失去上下文的小段。本次《先主传》翻译
和提取都在一次请求中返回了完整响应，因此这次没有必要测试逐段翻译。

超长章节需要明确保留容量失败和完整来源。若后续引入章内分批，应单独固定
语义范围、上下文、完成覆盖及整章复核合同，不能静默截断或用摘要冒充译文。
流式接收能改善进度观察，不能代替输出容量和恢复设计。

## 建议的阶段关系

```text
冻结来源、自然章与处理配置
        │
        ▼
整章纯译文（单/多模型） → 保存每个模型候选
        │
        ├── 完整原文 + 固定候选集 → 译文复核/对比 → 保存选定译文
        │
        └── 完整原文 → 实体、事件事实、人物状态、地点归属提取
                              │
                 固定译文 + 已核验的提取结果
                              ▼
                   译文关联、时间/状态核验
                              ▼
                  跨来源核对与连续叙事生成
                              ▼
                   内容复核 + 发布条件检查
                      ┌───────┴───────┐
                   满足条件        实质异议
                      │               │
                  原子发布        AI 有界修正
                                      │
                                仍无法解决再人审
```

这里是应用工作步骤，不创建另一套顶层任务队列。应在既有 IngestionJob、run、
租约、`ingestion_outputs`、ReviewItem 和发布事务内实现。来源生产的子步骤仍
由现有章节生产入口承接；综合叙事仍由当前 `present` 路径承接。

提取的事实依据是原文，不能由未经复核的译文反向证明事实。提取若完全只依赖
原文，可与翻译并行；译文关联必须等待译文版本固定。若为了减少等待提前使用了
候选译文，必须把该版本记录为依赖，修订后使受影响关联失效，不能沿用旧审核。

同书前章的压缩简介可以是可复用辅助上下文，保留实体线索、时间和未知项，
并绑定产生它的来源/产物版本；需要核实的细节仍回到原文。摘要不是新史料，
多个摘要也不增加独立佐证数量。摘要生成不应成为每个小任务重复的一次调用。

## 每个 AI 步骤的最小配置与留存

固定步骤及依赖即可，不需要先建设任意工作流编辑器。

| 项目 | 需要固定的内容 |
| --- | --- |
| 执行模型 | 一个或多个 provider/model 配置；单模型模式也保留同样的候选结构 |
| 汇总/复核模型 | 与执行模型分别配置；一个候选无需做无意义的多稿拼接，但仍执行该节点规定的内容检查 |
| 执行约束 | 并发上限、单次总时长、输入/输出预算、运输重试和内容修正次数；换模型产生新配置版本 |
| 输入身份 | 来源 revision/hash、章节范围、各上游产物 hash、prompt/schema/policy 版本 |
| 单次尝试 | 原始响应、完整/截断/超时状态、实际模型、用量、耗时、校验报告；失败稿同样留存 |
| 汇总结论 | 消费的候选/报告 ID、逐项差别、采用/拒绝/待定理由、最终产物及其 hash |
| 继续条件 | 规定的执行/复核完成，引用与版本合法，实质问题已处理；缺少规定模型结果不能伪装成一致通过 |

候选返回并保存、引用校验通过、语义复核通过、可发布，是四个不同状态。
未返回完整结果的模型调用是技术失败，不能记作赞同、弃权或“没有异议”。
重试预算耗尽可暂停供操作员处理，不把网络失败伪装成历史争议。

检查点采用完整输入和配置指纹。换来源、模型、提示、规则或上游文本后重新
计算受影响节点；未受影响阶段可复用。多模型并行写入独立尝试，汇总引用固定
集合，迟到结果不能覆盖已经选定的新版本。模型调用在 DB 事务外，回写须检查租约。

## 对比和人工审核的含义

对比围绕具体事实、覆盖范围及语境，不围绕文字相似度。两稿措辞不同且意思
相同，可以自动统一表达；谁担任官职、谁属于哪方、何时何地发生等差异才是
需要解决的语义问题。

AI 汇总不是投票，也不是直接拼接几份稿子：

- 同一原文产生的多个模型回答，不是多份独立史料；一致只能增加检查信息，
  不能证明历史真实。
- 汇总要保留少数意见并回看原文。审核模型也可能漏检、错引、误判，不能把
  一条审核建议直接作为纠错指令。
- 汇总驳回有据的实质意见，也要提供能够解释分歧的依据。仅说“也可以这样理解”
  不等于消除了争议；可由更适合该任务的模型做一次有界复核，仍不明再交人工。
- source ID 或 quote 存在，只能证明引用存在；还要检查引用是否支持具体
  主体、官职、时间和归属。不得把“曹丕称帝”挂到曹操的状态上。
- 史料中的传闻、引文和注家异议保留归属。两个时期的不同职位可以同时正确；
  没有提到不等于反证；无法确定时保留明确/不明确的区别。
- 有明确依据的修正仅修改相应产物/字段，保存新版本后重验关联；不靠重写
  全文解决一个引用或身份字段错误。超过有界修正次数仍存在实质疑问再人审。
- 人工页面显示冲突位置、相关上下文、各模型意见和 AI 的建议；允许展开完整
  章节，并在当前审核位置继续下一项。技术 ID 和全部尝试历史放在可展开详情。

最终仍需检查实体/日期/来源引用、正文覆盖、原注归属、相关审核版本和发布
依赖的一致性。网页只读已经发布的完整版本，不在滚动时生成内容。

本次试验反复出现逐字抄录原文引文时的空白、异体字和段号错误。后续优先考虑
让程序提供固定的来源片段句柄，由模型选择句柄，程序解析回真实原文和坐标；
片段是定位单元，输入上下文仍是完整章。不能用模糊匹配悄悄替换错误引用，也
不能因句柄有效而略过语义支持检查。

抽取的事件事实不等于导航锚点。任职、领有某地等信息保存为状态/事实；前台
入口仍由综合叙事选择少量重要事件或时期，不能重新给每个细节造一个锚点。
可参考既有 [综合叙事合同](../../../apps/chronicle/docs/source-corroboration.md)。

## 实施之前要同步的合同

当前 [chapter-production.md](../../../apps/chronicle/docs/chapter-production.md)
§2.2–§5 仍规定正文和原注全部翻译、整章联合输出及联合产物接受。本方向需要
显式的新阶段/产物版本和入口接线，不能直接让试验产物冒充既有 0.2/0.3 accepted 章。
旧试验和旧 schema 的解释保留，开发测试可用全新数据库，无需为旧数据做迁移。

当前 [source-corroboration.md](../../../apps/chronicle/docs/source-corroboration.md)
规定两次显式审核和人工选择综合来源；自动审核/发布需要具体更新这些应用规则，
同时固定自动处理的来源范围，不能默选全库或重写所有公开版本。

若自动决策涵盖跨来源身份 same-link，现行
[Amendment 0007 §5](../../architecture/amendments/0007-chronicle-resolution-review-subjects.md)
及 [review-publication.md 的 Key contracts](../../../apps/chronicle/docs/review-publication.md)
保留人类决定的权威，需要先按 Architecture Index 提交有确切受影响条款的
Amendment。不能用“AI 汇总通过”绕过现有身份、负约束和 canonical ID 边界。
这是实施前的合同变更点，本讨论记录没有擅自改动该权威。

## 后续拆分依据

| 顺序 | 有界交付 | 关键验收 |
| --- | --- | --- |
| 先固定合同 | 纯译文、阶段输入输出、来源边界、模型配置、自动决策权限 | 能明确区分保存/校验/复核/发布；新旧版本含义清楚 |
| 可并行 A | 阶段产物与恢复，在现有 store/worker 内接入 | 中途终止后不重调已完成翻译；输入变更拒绝旧检查点；失效租约不能提交 |
| 可并行 B | 整章纯文本翻译适配与原文定位 manifest | 一个完整章一次翻译；无注释/列表；完整响应和失败状态保存；定位由程序持有 |
| 可并行 C | 独立提取与译文关联适配 | 完整原文上下文；引用可定位；状态主体正确；重大导航与普通事实分开 |
| 合同固定后独立开发 | 节点单/多模型执行、候选比较和汇总 | 单模型可运行；多候选全留存；意见全覆盖；少数异议不丢；失败不当作一致 |
| 接入后串行 | AI 有界修正、人工例外与自动发布 | 仅修受影响节点；未解决异议阻止相应版本发布；旧审核不能批准新稿 |
| DTO 固定后可并行 | Studio 配置、阶段进度和连续审核交互 | 看得见各模型/阶段状态，错误定位可读，审核下一条无需滚回顶部 |
| 最后整体验收 | 固定语料、故障恢复、真实内容与浏览器 | 既验证生成能完成，也验证内容和公开页面；没有只凭 fixture 关闭真实验收 |

表格是下一轮任务的边界依据，不是已经创建的执行 Issue。实际拆叶时再按确定
接口划定独占文件；共享 schema、worker 入口、迁移与提交串行协调，避免合并冲突。
