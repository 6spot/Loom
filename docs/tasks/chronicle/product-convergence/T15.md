# C3-T15：建立背景素材上传、保存关联与受控读取后端

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

现有 skill 和离线图库只能生成并归档候选，产品没有上传保存与展示入口。必须区分图片文件、候选预览和针对精确正文版本保存的关联；上传成功不代表公开展示。

## 前置与文件归属

前置：[C3-T10 / #719](https://github.com/6spot/Loom/issues/719)、[C3-T13 / #722](https://github.com/6spot/Loom/issues/722)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

新增应用背景 asset/binding 模块和迁移、内部 Studio/公开资源路由；Rust 在现有代理增加对应受鉴权/公开边界。更新 `docs/background-art.md` 的实际格式和 API，并更新 Chronicle 部署的素材卷/备份说明。该路由接线在 T13 后串行。

## 实施步骤

1. 定义 asset（服务端 UUIDv7、内容 hash、格式/尺寸、来源/时代/提示词等元数据）与 binding（确切 history version、起止 paragraph ID、asset version、浓淡/位置/遮罩、保存记录）。首版只绑定主历史 edition，不兼容 source stream 坐标。
2. Studio 独立图片上传接口接收 PNG/JPEG/WebP，首版上限 8 MiB、总像素 4000 万；实际解码核验格式/尺寸，拒绝 SVG/HTML、伪 MIME、解码失败和超限。服务端生成存储路径，文本 revision API 不接受图片。
3. 素材置于 Chronicle 自有持久目录，候选预览必须鉴权。文件落盘并校验成功后登记候选；失败不留下可公开的半文件/半记录。
4. “保存并显示”在事务中核验文件、素材版本、已发布 edition、精确起止段和合法显示参数，再启用 binding。首版同一正文位置最多一个有效关联；重叠保存明确报冲突，替换通过显式操作完成。
5. 保存、替换、停用均留审计。一张图可复用，停用一处不影响他处；新正文版本不继承旧坐标。绑定响应有 revision/etag，读者按返回配置加载，不擅自刷新为新图。
6. 公开图片接口仅允许当前有效已保存关联引用的资源；文件 ID 不直接拼文件路径，未保存/停用候选不可通过猜 ID 读取。普通阅读、上传和发布章节均不调用图像生成。

## 验收标准

- [ ] 未保存候选仅管理员能预览；保存后仅指定版本/范围可读；停用该关联后不能通过该关联读取（其他有效关联不受影响）。
- [ ] 伪格式、超像素、超字节、路径穿越、未知段落、错版本、重叠绑定均明确失败。
- [ ] 同图两处绑定独立，替换/停用一处不改另一处；新 edition 不自动继承。
- [ ] 重启后素材/设置仍可读取，写入失败不产生公开半成品；备份/恢复范围包括图像文件和元数据。
- [ ] 全部入口无图像模型自动调用，图片生成仍在用户主动 skill 流程中。

## 验证方式

运行解码/参数单元测试、真实文件存储及 PostgreSQL 事务测试、Rust/Studio 鉴权与公开资源 HTTP 测试。用一张古代图和一张近现代图验证，不自动生成新图作为测试前置。

## 不在本叶内

不增加自动配图服务、不把图插入正文、不扫描开发机图库决定发布、不修改现有文本上传合同。
