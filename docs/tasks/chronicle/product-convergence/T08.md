# C3-T08：统一后台上传、任务进度、模型对比与异常审核页面

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

当前后台能上传、看结果和审核，但任务类型不同就出现不同的低效展示。要让编辑以正文和各方意见做判断，保存/下一项始终可达，并能准确重试失败步骤或创建换模型的新执行。

## 前置与文件归属

前置：[C3-T07 / #716](https://github.com/6spot/Loom/issues/716)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `webapp/src/pages/studio/StudioImportsPage.tsx`、`StudioImportDetailPage.tsx`、`StudioReviewDetailPage.tsx`，以及 `components/studio/` 中现有步骤/结果组件和 `lib/studio-workspace.ts`、`studio-api.ts`。共享接线由本任务统一处理，不与 T16 同时修改 StudioLayout/App。

## 实施步骤

1. 上传后直接进入该任务工作区。左侧为可读步骤及进度，中间为当前稿/对比，右侧按需展开来源和模型意见；大段代码移入“技术详情”。复用现有 Studio 组件与样式，不另建管理站。
2. 任务列表突出资料/历史范围、当前步骤、失败/待审原因和下一步操作，默认不铺开原始 ID。空分组整体隐藏。
3. 对比按同一结论或段落对齐展示各模型说法、采用稿和理由；模型输出必须完整可读，长结果按 T07 分页。不能只显示几字参考，也不默认把全部 JSON 展开。
4. 页面底部持续可用：保存/通过/驳回/下一项/返回。保存失败保留草稿与位置；只有成功响应并校验候选版本后才能移到下一项。
5. “重试”继续同一冻结执行；“更换模型重跑”展示所选模型和新任务关系，保留原记录。按钮启用状态使用 T07 的 actions，不猜测内部状态。
6. 通过现有浏览器脚本演练实际 source/history 任务，检查加载、空态、错误、长稿和连续审核。布局可参考已有设计 skill，但不得另加审批或独立原型交付。

## 验收标准

- [ ] 非技术用户能从任务列表进入，指出正在执行哪一步、为什么停住和能做什么。
- [ ] 完整原文、完整候选、所有模型意见可在当前任务内查看；未出现仅靠内部编码识别对象的主界面。
- [ ] 滚到长稿底部后直接完成审核并进入下一项，无需滚回顶部。
- [ ] HTTP 失败/版本冲突/重试失败保留编辑与定位；不能假显示成功。
- [ ] 使用真实 T07 API 验收上传→处理→异常→查看上下文→修订/通过→继续；只用静态 fixture 不算完成。
- [ ] PC 布局、键盘顺序、Escape/焦点恢复及窄屏基本可用，无横向溢出。

## 验证方式

运行受影响 Vitest、构建/dist 检查、studio-workspace 与相关 review 浏览器 suite；保留真实任务截图、操作结果和 API 版本。

## 不在本叶内

不修改读者主历史布局，不增加后台自动触发图片生成或让浏览行为修改生产状态。
