# C3-T01：用当前分阶段合同统一来源生产验收与测试夹具

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

目前正式入口只接收 staged 0.4，但 first/second/third round gate 及大量模型夹具仍构造 0.1–0.3 联合产物。后续删除旧分支前，必须让有效的验收用当前链路执行。测试版本陈旧不能成为长期保留旧生产实现的理由。

## 前置与文件归属

前置：无；可在本轮清理交付后开始。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `apps/chronicle/acceptance/`、`worker/staged_pipeline_fixture.py`、相关 gate 测试与 Chronicle CI 的验收调用。更新 `docs/staged-chapter-production.md` 的验证入口和 `docs/chapter-acceptance.md`、`reading-acceptance.md`、`person-state-acceptance.md`。本任务不改历史正文样式，也不改候选的语义校验。

## 实施步骤

1. 以 `staged_pipeline_fixture.py` 为唯一当前模型夹具，按完整原文生成 translation、extraction、linking、review 的预设响应；不能直接伪造 accepted artifact 或绕过内容 acceptance receipt。
2. 把现有 gate 的实际场景迁到一个当前验收入口，复用 `gate_runtime.py` 的数据库/服务生命周期。支持 `fixture` 和 `live` 两种显式模式；live 禁用 fixture，禁止失败后自动换成 fixture。
3. 保留覆盖：整章首尾、别名、两个来源同一人物、同名异人、状态阶段、原文引用、事件锚点、失败重试、取消/租约接管、原子发布。按场景组织，不再按旧轮次复制一套启动/写库代码。
4. 将真实质量判读和程序检查分开记录。人工判读使用已经入库的完整章节及对应输出；脚本检查结构/引用不声称证明史实正确。
5. 替换 CI 和当前指南的调用后删除失效 gate 入口及专属 helper。历史任务和已归档验收结果保留；不要批量删除 corpus。

## 验收标准

- [ ] 空 PostgreSQL 18 测试库从上传/排队经过真实 0.4 各步骤，产物包含可重验的完整 step history 和 acceptance receipt。
- [ ] 同时覆盖公开来源阅读、人物状态、综合历史三个消费方；任何一个失败，gate 退出非零，报告给出场景和位置。
- [ ] 重试不重复成功步骤；进程重启后能够继续；内容未接受时公开接口没有半成品。
- [ ] 现行 CI/指南只有一套该验收入口。旧版本兼容不再是 gate 的前置条件。
- [ ] live 模式缺凭据明确失败，不打印密钥，不把 fixture 结果标为真实模型成功。

## 验证方式

运行迁移后的 fixture gate、自身参数/模式测试及受影响的 worker 测试；真实模型验收复用现有已授权环境与配置，记录模型、章节、每步结果和耗时。环境不可用时明确记录未完成的 live 验收，不能用 fixture 替代。

## 不在本叶内

不在此任务更换数据库状态机、增加另一套任务队列或修改左侧时间轴设计。
