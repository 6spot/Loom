# 先修复真实主历史入口的人物页（沿用 #699）

这是已有 [#699](https://github.com/6spot/Loom/issues/699)，不另建重复任务。
本叶改善当前已有内容的呈现，T12–T14 再交付专用生平生产与阅读。

## 已确认的问题

`EntityPage.tsx` 默认仍显示 Source representation、Claim/Resolution、事件卡和
内部 phase/paragraph ID；`HistoryPhasePanel` 对找不到指定段落仍有取首段的
回退。页面混合来源 reading locator 与主历史 locator，尚未形成清楚的人物
阅读职责。主历史页已经清理的阶段标签不再重复当作本叶未完成项。

原始真实证据来自 `apps/chronicle/corpus/second-round/acceptance/staged-live-20260913/`。
入口为：

```text
/history/9684d395d97aa5fb28811c3fd18512c3742f2cdda5371734763d5ab020e3ceff/hp_b8d99fecf152b8a8a0caff74
```

从该段周瑜行进入人物页。使用新数据环境时，重新通过正常流程生成对应的已
审核周瑜资料，不要求迁移这个历史测试版本，也不能用模拟人物介绍替代验收。

## 文件归属与做法

本叶拥有 `webapp/src/pages/public/EntityPage.tsx`、人物呈现组件、相关查询与
测试。T14 在此叶完成后再修改这些文件；T01/T09 与此叶可以并行。

1. 保留主历史固定版本、段落和段内返回位置。指定段不在响应中时显示无法定位，
   不能取第一段；使用真实段的阶段信息，不能信任任意 URL phase 值。
2. 默认突出姓名、已有审核介绍或自然空态，以及当前资料支持的经历和阶段状态。
   没有专门人物生平时如实说明范围，不能把主历史筛选片段标成完整传记。
3. 身份区显示官职、爵号、效力，相关人物/地点只作辅助。经历只出现一次；
   不用“率军南下”等动作填状态，不将后期官职补到早期。
4. 来源、不同说法与技术记录放入主动打开的资料层，默认隐藏。读者界面不出现
   `hp_…`、`p_east`、canonical、grounding、predicate 或原始 JSON。
5. 沿用明确/存疑的逐项标记；缺数据时不显示空栏目。失效 locator、取数据失败
   和介绍缺失分别有正确状态。
6. 实际查看主历史入口、source reading 入口和直接访问人物页，避免只把新面板
   接到一种来源。直接访问不能擅自替用户选某个年份。

## 验收

- [ ] 使用真实周瑜资料，从主历史进入可以看到可读介绍/空态、相关经历及准确当时状态。
- [ ] 早期、居巢、赤壁与南郡阶段的官职/效力各自核对；未知/存疑不会被填满。
- [ ] 来源/分歧默认收起但可展开到原章；默认没有内部代码与英文协议说明。
- [ ] 找不到段落不展示第一段状态；网络错误可重试，返回始终恢复原版本/段落/段内位置。
- [ ] 1440px、390px、320px 浏览器检查与键盘操作通过，无横向溢出。
- [ ] 提供真实 API、版本和截图证据；相关 Vitest、build/dist 和人物浏览器场景通过。
