# C3-T13：提供人物生平分页与主历史阶段对应的读取 API

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

人物生平需要独立版本、段落分页、状态与原文，并能从主历史中可靠定位。现有 entities/{id} 的 trajectory 不等于独立生平正文，也不能把 URL 的 phase_id 直接当作可信状态。

## 前置与文件归属

前置：[C3-T10 / #719](https://github.com/6spot/Loom/issues/719)、[C3-T12 / #721](https://github.com/6spot/Loom/issues/721)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改新增人物阅读 repository/router，`read_api/router.py`、`server/src/app.rs` 的子路由及测试。只从 Chronicle persistence 读取 T12 已发布版本；不要让 Rust 访问数据库。公开路由接线在 T10 后执行，T15 随后执行。

## 实施步骤

1. 定义 `/api/v1/public/entities/{id}/history` 的已发布人物元数据，以及固定人物版本的段落/结论读取。沿用已有历史分页/错误风格，单页不超过 50 段。
2. 入参包含来源主历史 `{version, paragraph_id}` 时，只通过 T12 发布的对应表返回个人定位。返回 mapped/unmapped/ambiguous 的明确结果；多个目标让读者选择，不能取第一条。
3. 元数据包含姓名、已审核概况、时间精度、资料覆盖范围和首段；每段带个人阶段状态及关联对象。没有生平发布返回真实空态，不现场生成。
4. 精确校验实体身份、人物版本、paragraph/conclusion 归属；主历史同名人物、同一年份或局部阶段 ID 不形成跨版本映射。
5. 原文引用仍指向真实 source publication/anchor。默认元数据与正文不铺开全部证据，依据按需另读。
6. Rust 只校验路径/方法并转发，认证后台生产与匿名公开读取仍分离。

## 验收标准

- [ ] 同一个人物两份版本可独立分页，旧链接不会读到新稿。
- [ ] 从主历史周瑜早/晚阶段分别得到正确个人位置和状态；缺对应/多对应显式返回，不误定位。
- [ ] 其他人物的版本、未知段落、未发布稿和坏参数均被拒绝。
- [ ] 分页内容有完整前后位置，依据可展开到原章，GET 不触发模型或写入。
- [ ] API 只返回真实已有内容，没有把事件 actions 自动转成职位/阵营。

## 验证方式

运行人物 read API 的 PostgreSQL 定位/分页/越界测试、Rust 代理测试，保留至少两个真实阶段的脱敏响应供 T14 直接使用。

## 不在本叶内

不实现页面、不按名字搜索来代替身份解析，不创建另一个人物事实库。
