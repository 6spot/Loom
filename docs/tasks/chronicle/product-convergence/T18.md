# C3-T18：收敛旧公共导航和百科式页面，删除被替换的实现

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

主历史、人物生平完成后，旧 World/Timeline/事件资料卡仍是有效路由，不能继续通过“更多”入口把用户带回旧产品。退役要同时迁移真实链接和保留深层依据，不能只删页面文件留下死链。

## 前置与文件归属

前置：[C3-T14 / #723](https://github.com/6spot/Loom/issues/723)、[C3-T17 / #726](https://github.com/6spot/Loom/issues/726)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `webapp/src/App.tsx`、`SearchPage.tsx`、旧 `WorldPage.tsx` / `TimelinePage.tsx` / `EventPage.tsx` 及其专属 query/CSS；对应 Rust SPA allowlist 和当前页面文档由本任务统一调整。HistoryPage 的共享接线在 T17 后执行。

## 实施步骤

1. 对 App、搜索结果、人物经历、事件词、返回链接做一次实际调用清单。主导航只负责历史入口、连续阅读、检索和人物；来源书/章保留为资料查看入口。
2. `/world`、旧事件列表 `/timeline` 退役；不保留兼容跳转或第二套首页。移除未使用的页面、专属样式/query 和仅测试旧路由的断言。
3. 事件词/事件搜索优先定位到已发布 edition 中的精确发生位置；多发生位置提供可读选择。没有经过审核的正文对应时展示“暂无对应历史正文”和深入的原来源入口，不猜年份/标题或跳到第一段。
4. 旧 EventPage 的直接 Source/Claim/Resolution 卡堆叠退出默认公共体验。需要的原文/不同说法放入已有阅读资料层；不要为过渡再造百科页。
5. 人物检索到 T14 独立人物页；地点保持有据状态与相关历史定位，不把地点套成人物生平。仅从实际已发布映射导航，不把所有小事件自动升为精选锚点。
6. 清理没有调用者的 API/client helper。仍供当前状态、搜索、Studio 或依据读取使用的接口保留；对决定退役的公共接口显式返回未找到，内部 Python 协议按实际调用处理。
7. 更新页面清单、实际 Rust shell 路由和浏览器测试；不要把历史任务记录中的旧截图当作当前要求。

## 验收标准

- [ ] 首页→历史→人物/事件→原位返回均走已发布版本，无旧百科卡布局或书籍阅读主入口。
- [ ] 搜索重要/非重要人物与有/无叙事对应的事件均有正确结果，不出现死链或擅自定位。
- [ ] 退役路径不再加载旧模块，当前源资料引用仍能展开到完整原章。
- [ ] React 路由、Rust 刷新路径与所有当前内部链接一致；旧页面专属模块/样式已删除。
- [ ] 当前 history/person/Studio/来源查看回归通过，确定性检索和身份不确定性规则没有被破坏。

## 验证方式

运行实际路由/API/导航测试、build/dist、Rust server 测试与真实浏览器入口/返回场景；交付删除清单和保留依据能力的证据。

## 不在本叶内

不开发新的百科、图书馆、全球地图或倒序阅读；事件独立长篇叙事将来可在同一版本/锚点体系扩展，本叶不另造一份事实数据。
