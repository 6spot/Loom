# C3-T02：收敛章节 schema、校验与装配为当前 0.4 合同

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

0.4 schema 仍引用 0.1 的基本字段、0.2 的阅读字段和 0.3 的人物状态字段。旧文件有活跃依赖，不能按版本号直接删；需要把仍有效的定义提取出来，再退役旧的顶层协议。

## 前置与文件归属

前置：[C3-T01 / #710](https://github.com/6spot/Loom/issues/710)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `ingestion/schemas/chronicle-chapter-*.schema.json`、`persistence/chapter_contract.py`、`staged_chapter_contract.py`、`assembly.py` 与对应合同测试；按实际引用调整 `reading_contract.py` / `person_state_contract.py`。章节编排的旧 C1 分支归 T03。

## 实施步骤

1. 建立唯一的当前共享定义文件，明确 source/bundle、译文与原文锚点、reading、person_states 各字段的所有者；0.4 candidate/artifact 只引用当前定义，禁止回指已退役顶层 schema。
2. 保留已验证的坐标、原文 hash、主体、阶段、范围、引用和内容接受校验。复用验证函数，不复制两套“新旧 validator”。
3. 正式注册表只接受当前版本；显式传入 0.1/0.2/0.3 应报 unsupported version。不得静默升级输入、补造 acceptance receipt 或保留兼容开关。
4. 装配只消费全部预期的 accepted 当前章节。保留 local-ref 到 revision-ref 的唯一映射、person-state manifests、reading compile 所需信息。
5. 将仍有价值的旧测试改为当前合同的正反例；删除仅证明已退役协议可接受的测试和 JSON 文件。完成引用扫描后再删定义。

## 验收标准

- [ ] 当前有效样本通过；旧顶层版本、未知字段、越界引用、错章/错阶段/错 hash 均失败。
- [ ] 中文繁简处理不改原文坐标或引用内容；正文仍为完整简体译文。
- [ ] 缺一章、缺 accepted receipt、缺人物状态 evidence manifest 均不能装配发布。
- [ ] 相同输入产生相同 artifact/assembly hash；resume 不因定义迁移额外调用模型。
- [ ] 当前代码与 schema 不再引用退役的 0.1–0.3 chapter 顶层文档，T01 gate 通过。

## 验证方式

运行受影响的 chapter/reading/person-state 合同和 assembly 单元测试，以及 T01 当前 fixture gate。复核对当前有效样本的校验能力没有降低。

## 不在本叶内

不移除 Source/Entity/Event/Claim 基础格式中的版本号；它们与 chapter 顶层协议不是同一个合同。无需旧测试数据库迁移或兼容读取。
