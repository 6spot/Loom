# C3-T03：删除 C1 分块生产、重复 presentation 与旧运行器分支

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

本轮清理已撤掉旧部署入口，但库中仍有 C1 2000 字分块执行、chunk_model/presentation_model、旧参数、假执行旁路。它们与当前章节分阶段链路并存，后续模型很容易接错路径。

## 前置与文件归属

前置：[C3-T02 / #711](https://github.com/6spot/Loom/issues/711)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `worker/ingestion_worker.py`、`chapter_stage.py`、`model_provider.py`、`presentation_stage.py`；清理 `persistence/segmentation.py`、`extraction.py`、`assembly.py` 中已无当前调用的部分。更新 worker/旧 C1 指南和相关测试。`catalog_publication.py` 与 `identity_candidates.py` 的当前语义保持不变。

## 实施步骤

1. 从 JobRunner 的真实源路径移除 `_load_real_plan`、`_execute_real_extract/assemble/resolve/publish` 等旧 C1 分支及其专属参数、常量和 helper；先列调用者，当前复用的逻辑迁到唯一正式模块。
2. 有原文任务只走当前自然章流程；综合任务走其明确的 job kind。未知类型或缺配置在领取/执行边界失败，不落到假成功。
3. 去掉旧 `models_from_env` 对 extraction/presentation 的配置入口及无调用的格式构造器。保留当前 staged transport、narrative transport、全局 timeout、错误脱敏和有限重试。
4. 将生命周期故障注入所需的 StageExecutor/假拓扑隔离到测试支持。正常 prepare 记录真实的准备元数据，不能把整条生产假执行作为默认值。
5. 删除仅服务旧路径的测试、脚本和文档正文；把仍有效的租约、取消、原子提交、不重复成功工作等场景移到 T01 当前夹具。Rust control_plane 仍是生命周期合同，不因删除旧 Python 编排而改变。
6. 用实际 import closure 和调用检索核对残余文件。CLI、迁移入口、离线语料工具不能仅因没有静态 import 就判死。

## 验收标准

- [ ] 正式运行器不再出现 chunk_model、presentation_model 或 allow_fake_after_real_source 选择分支；旧环境变量不启用行为。
- [ ] 缺模型、缺原文、非法任务类型均明确失败，公开页面无假内容。
- [ ] 领取排他、租约过期、取消、接管、review/resume、成功步骤复用和原子发布均由当前流程测试覆盖。
- [ ] 当前身份候选与发布负约束测试通过，不因“多模型同意”取消人审身份决定。
- [ ] 当前 gate、全部受影响单元/数据库测试通过，开发指南只保留正式生产指令。

## 验证方式

运行 worker 单元测试、当前 staged/production PostgreSQL 测试、identity/catalog 发布测试和 T01 gate。交付中列出删除的分支，以及原安全场景迁到哪些当前测试。

## 不在本叶内

不删除仍被当前协议调用的字段或验证器；不为了删旧代码重写 Loom 引擎、改变已有八阶段状态机。
