# C3-T04：把已验证的分步骤执行机制提取为可复用组件

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

整章流程已有结果保存、多个模型、对比、有限纠错、恢复和租约约束；综合事实/叙事还自行编排。需要复用执行机制，避免每加一种生产稿就出现另一套 retry、timeout 或状态。

## 前置与文件归属

前置：[C3-T03 / #712](https://github.com/6spot/Loom/issues/712)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `persistence/chapter_production.py`、`chapter_production_store.py`、`worker/chapter_models.py` / 当前 transport；按职责新增应用内共用 step 模块并让原章节实现改为其调用者。同步 `docs/staged-chapter-production.md`。不改 Studio 页面。

## 实施步骤

1. 先从现有实现提取步骤定义、依赖、模型 profile、输入 fingerprint、attempt、输出和验收引用的公共类型。步骤业务校验通过明确 adapter 注入；不把原文/译文语义放进通用 runner。
2. 通用执行器使用原 IngestionJob、ingestion_outputs 和现有租约；每步先保存结果再启动依赖。没有依赖的步骤按冻结 max_parallel 执行。
3. 相同输入/profile/协议的成功步骤直接复用。失败或未完成步骤有限重试；启动即消耗 attempt。没有完整模型返回不能充当同意。
4. 保留每个模型的独立结果、原始异议、比较选择理由和修订链。选择一个结果不删除其他候选。
5. 统一使用 CHRONICLE_MODEL_TIMEOUT_SECONDS；不新增单步硬编码时间。模型调用期间不持有数据库事务，取消/丢租约中断等待并禁止迟到写入。
6. 章节 adapter 迁入同一组件，删除搬迁后的原实现；不保留 chapter runner 和 generic runner 两个活动副本。

## 验收标准

- [ ] 章节路径仍完成 T01 全流程，产物和引用语义保持一致。
- [ ] 测试 A/B 可并发、C 依赖两者：C 不会提前；B 失败后重试只跑 B/C，不重复 A。
- [ ] 多模型中一项失败、输出截断、比较结果格式错、复核有异议均不能自动通过。
- [ ] 保存后崩溃、取消、丢租约、预算耗尽有确定终态，保留已有记录。
- [ ] 仅有一处生产 timeout 读取规则、一处 attempt/恢复规则、一套输出存储。

## 验证方式

运行通用 runner 的依赖/恢复/取消测试，章节单元与 PostgreSQL 流程回归及当前 gate。不要为每个 adapter 重复制定相同的基础测试环境。

此任务只是复用机制，不开启综合任务自动发布，不修改身份等价或审核权限。
