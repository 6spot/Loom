# C3-T11：让主历史阅读无缝跨越多个生产片段

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

当前页只在一个最多 256 段的叙事内分页。T10 将公开 API 切到全局版本后，需要保持一个阅读控制器和一个固定版本，在片段/时期交界处持续预读、定位和显示状态。

## 前置与文件归属

前置：[C3-T10 / #719](https://github.com/6spot/Loom/issues/719)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `webapp/src/lib/history-api.ts`、`narrative-types.ts`、`pages/public/HistoryPage.tsx` / `HomePage.tsx` 与历史窗口适配；复用 `useReadingPosition`、现有轴与返回位置。修改共享 window hook 时覆盖来源阅读消费方。

## 实施步骤

1. 从最新 edition 获取首页精选入口；点击入口进入固定 version+paragraph，不设置事件或时期过滤。
2. 正文窗口只加载当前位置和相邻页，越过片段边界仍向相同 edition 请求下一页。预读失败可就地重试，已经看到的正文不能清空。
3. 左轴按 edition 的审核导航显示，随正文跟随。边界不是折叠分组或大标题；不增加“从下一篇读起”中断页。
4. 右侧人物/地点按当前全局段绑定的真实阶段更新；禁止复用前一片段的状态、上一事件背景或仅凭同年份找状态。
5. 人物/证据往返与浏览器前进后退保留固定 edition 和段内位置。最新版本变化不打断已打开的会话。
6. 保留窗口回收和稳定高度，避免无界 DOM。API 元数据/页面结果按 version 隔离，快速跨锚点的迟到响应不得覆盖新位置。

## 验收标准

- [ ] 3 个片段、300+ 段从首片段中部连续读到末片段，交界无跳页、重复、突然清空或筛选结束。
- [ ] 跨边界人物职位/效力正确变化；未知阶段不沿用上一段状态。
- [ ] 左轴自动跟随、手动浏览暂停、回到当前位置及零精选入口区间均可用。
- [ ] 网络错误保留可读正文，重试后续接；快速跳锚点与浏览器返回不串版本。
- [ ] 真实 T10 API、PC 浏览器和证据往返通过，DOM/窗口数量保持现有有界策略。

## 验证方式

运行 history API/window/position 单元测试、构建/dist 和 history-component smoke；另以真实 PostgreSQL edition 验证跨批次。复用成功的通用阅读测试，不用单批次 fixture 宣称跨批次完成。

## 不在本叶内

不实现倒序历史、不生成标题 slug、不在正文插入导航横幅；手机时间轴重设计仍另行讨论。
