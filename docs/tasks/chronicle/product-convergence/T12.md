# C3-T12：生产独立的、有依据的人物生平叙事

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

现有人物资料页有事件轨迹和部分阶段状态，没有专门生产的生平正文。不能把筛选出来的主历史段落称作完整传记，也不能在浏览器临时让模型补一段简介。

## 前置与文件归属

前置：[C3-T06 / #715](https://github.com/6spot/Loom/issues/715)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

新增 `docs/person-history.md`、人物叙事合同/生产 adapter，复用 T04/T05 的模型执行与 facts/prose 机制、`identity_candidates` / 已发布 canonical 身份。数据库写入留在 `persistence/`。避免直接修改 T10 正在处理的主历史查询；共享 job dispatch 按 T04 的注册方式接入。

## 实施步骤

1. 合同固定 person canonical ID、所选完整已发布来源、上下文 hash、人物叙事版本、覆盖范围、概况和有序个人经历。生卒时间没有依据时为空，不能用第一次/最后一次出现推定。
2. 人物事实仍引用已有来源和批准结论，记录主历史阶段/段落的可靠对应。允许对应缺失或一对多；禁止按姓名或年份猜唯一对应。
3. 将简短概况与个人经历正文作为独立产物，通过相同模型结果留存、对比、内容接受/异常审核发布。姓名相同但身份未判同的人物不得混入。
4. 每个个人经历阶段明确关联当时职位、爵号、效力及相关人物/地点；动作写进经历，状态字段只表达状态。
5. 阅读范围说明与正文一起审核。有限资料只称“据当前收录资料整理的经历”，不声称已覆盖全部一生；不能为顺畅补写无来源故事。
6. 普通人物 GET 不触发生产；Studio 明确选择人物与来源排队。新来源/新稿形成新版本，旧结果不覆盖。

## 验收标准

- [ ] 周瑜可生成有依据的概况和连续个人经历，早晚官职/效力只出现在适用阶段。
- [ ] 同名异人、缺生卒年、状态存疑、来源矛盾、人物与主历史阶段无法对应都有明确结果。
- [ ] 每段可追溯到批准结论和完整原章；没有无依据的新事实或身份合并。
- [ ] 模型失败/异议/修订沿用 T04–T06 恢复与接受流程，不另起编排器。
- [ ] 原稿、各模型输出、接受记录、个人版本与主历史位置映射均持久可查。

## 验证方式

运行人物合同正反例和 PostgreSQL 完整生产/恢复测试；用当前完整周瑜来源做真实稿件检查，保留不同阶段状态及无法确定处的证据。

## 不在本叶内

不要求穷尽所有人物生平，不制作未授权图片；来源主阅读 stream 和人物叙事不是同一个 ID。
