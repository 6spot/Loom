# C3-T16：实现 Studio 素材库、正文背景预览与人工保存

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

操作员应能上传 skill 生成的图片，查看效果并明确保存到阅读位置。不能上传完自动启用，也不能只给一个文件列表而看不到正文中的真实效果。

## 前置与文件归属

前置：[C3-T08 / #717](https://github.com/6spot/Loom/issues/717)、[C3-T15 / #724](https://github.com/6spot/Loom/issues/724)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改新增 Studio 背景素材页面/面板、`lib/studio-api.ts`、`App.tsx` / `StudioLayout.tsx` 导航和相关 CSS/测试。使用 T15 API；T08 共享后台改动完成后再接线。

## 实施步骤

1. 素材库按时代/来源/使用状态提供检索、预览和上传；显示实际图像及制作信息，不把“候选”误标为已展示。
2. 从已发布历史位置或素材库进入设置面板，显示当前 edition、可读上下文和起止段范围；系统 ID 放到深层详情，不靠 ID 文本选位置。
3. 在同一面板预览正文和背景，调整浓淡、主体位置与遮罩；可以临时关闭背景比较。预览只在管理员面板内，不写公开关联。
4. “保存并显示”一次提交确切素材版本、范围和设置；成功后显示实际绑定状态。失败/冲突保留选择、草稿和当前位置，不提示已启用。
5. 提供显式替换/停用，展示影响的具体位置。已有素材多处使用不做全局替换。
6. 首版只实现用户上传和复用现有候选；AI 建议可以作为待确认信息展示，但不增加自动生成调用。

## 验收标准

- [ ] 上传→预览→取消：普通读者看不到；上传→调整→保存成功：指定范围可见。
- [ ] 错版本/重叠/服务失败保留编辑并展示具体错误，未出现上传即发布的中间状态。
- [ ] 编辑长正文背景时主要操作始终可达，可键盘预览、保存和返回。
- [ ] 同图多处使用、单处替换/停用的显示与 API 实际结果一致。
- [ ] 用 T15 真后端完成整条操作，截图包含保存前后的读者差异。

## 验证方式

运行 Studio API/组件测试、build/dist 和新增的背景管理浏览器场景；真实文件上传与公开读取联测。

## 不在本叶内

不调用模型自动生成图片，不开发独立图片编辑器，不把资料来源的章坐标冒充历史正文位置。
