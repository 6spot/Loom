# C3-T07：为所有生产任务提供统一且可读的步骤与结果 API

## 依据与执行边界

先读[本轮索引](README.md)及本叶涉及的当前规范。任务状态由现用管理工具维护；此处记录需求、接口、依赖和验收，不要求复制最终 PR/merge 元数据。开发阶段可以使用全新测试数据，退役实现无需兼容。有效来源、身份负约束、租约和发布保证仍须保留。

## 当前问题

Studio 已有章节进度及保存结果，但综合事实/叙事仍是另一种结构。用户需要清楚看到每个任务走到哪一步、哪一模型失败、哪些结果被采用，而不是阅读内部编码。

## 前置与文件归属

前置：[C3-T06 / #715](https://github.com/6spot/Loom/issues/715)。

下列路径均相对 `apps/chronicle/`（明确写出 `apps/`、`.github/` 或 `docs/tasks/` 的除外）；“新增”表示本任务交付，不假设文件已存在。

主改 `persistence/studio_production.py`、`read_api/studio_jobs.py`、`studio_reviews.py` 与对应 API/分页测试。同步 `docs/worker.md` 的结果投影合同。T08 按该合同实现页面；不在此任务改 React。

## 实施步骤

1. 为 source/history 等任务返回同一外壳：任务类型、人类可读标题、当前步骤、依赖关系、各步骤 status、可用操作及失败原因。稳定机器 key 与展示 label 分开。
2. 每个模型 attempt 返回模型名、次数、开始/结束/耗时、输出是否完整、校验/对比状态；用独立读取接口分页拿原始结果。列表不内嵌全章和大量 JSON。
3. 返回明确的 retry/resume/new-run 能力及不能操作的原因，来自真实 control-plane 状态，不由前端猜测按钮权限。
4. 返回合并稿与全部模型意见的关联；缺 usage 显示未报告，失败或无输出不能显示“已同意”。不同版本和来源关系必须可区分。
5. 公共 API 不暴露这些管理结果；Studio 继续受 Rust 鉴权。输出白名单脱敏，不返回密钥、完整 transport 配置或服务端路径。
6. 旧阶段代码可以保留在深层诊断中，默认投影全部提供可读名称。读取不启动模型、修复或重试。

## 验收标准

- [ ] 一个章节任务和一个综合任务都能读取完整步骤图，当前阶段、已保存结果和失败点一目了然。
- [ ] 2 模型有一项失败、等待人工、预算耗尽、取消、完成等状态的 actions 与真实操作结果一致。
- [ ] 大结果逐页读取且 hash/版本/任务归属正确；不能通过别的 job_id 读取不属于该任务的输出。
- [ ] 未鉴权请求失败，响应/错误无密钥；每个展示 label 均为简体中文。
- [ ] API 的读取不会修改 job、刷新预算或产生模型调用。

## 验证方式

运行 Studio jobs/reviews 的投影单元测试与 PostgreSQL/HTTP 权限和分页用例。保留两个真实任务的脱敏 API 结果供 T08 验收使用。
