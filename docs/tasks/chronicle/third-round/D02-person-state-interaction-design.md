# 人物阶段资料与依据审核的桌面、窄屏交互设计

## 范围与交接

[Issue #618](https://github.com/6spot/Loom/issues/618) 记录实施标准。在正式页面与组件中落实紧凑人物／地点状态、两档标记、人物详情和集中审核交互；沿用 C2-R2E 已接入的 HistoryPage，不再新建独立静态设计站。

- 输入：第二轮 reading-experience.md 的布局/字体/导航合同；第三轮本契约；现有周瑜、刘备原文核对点和明确标注的合成交互数据。

## 实施步骤

1. 画出 1440、1024、390、320 四种宽度：桌面右侧人物区，中屏展开区，手机人物地点入口；正文保持主位。
2. 默认每人／地点独占紧凑一行：人物显示官职、爵号、效力，地点显示行政归属／实际控制。经历、角色和变化进入人物详情。另做兼任、多阶段过程、阶段未明、暂无记载、同人部分明确的场景。
3. 用实心/空心标记及正常/灰墨色体现两档，给出可访问文字、对比度、触控面积；不把不明确项设计成 disabled。
4. 设计点击/聚焦后的原因、原文窗口、整章、相关事件入口及关闭回焦；不改变当前阅读阶段或新增全局时间控制。
5. 画出一章一个阶段依据包的审核页：按人物读变化，共用阶段依据、批量确认、逐条例外、固定保存并下一项、错误及草稿保留。
6. 明确独立人物页三栏：左侧概况与时间定位，中间按时间的个人经历，右侧当前阶段状态及相关人物／地点；从正文进入保留阶段，返回恢复原段和偏移，直接进入不捏造当前年份。
7. 以实际浏览器检查窄屏、200% 缩放与键盘，归档截图及操作说明；合成示例明确标识，不冒充真实内容验收。

## 验收

- [ ] 四种宽度均能操作正式组件场景；每人／地点独占紧凑一行，当前状态与人物经历分开，阅读主次和手机入口清楚。
- [ ] 正常、不明确、空、加载失败、兼任、分歧和 process/ambiguous 状态都有确定呈现。
- [ ] 颜色以外能辨识两档；正常/弱化文字都满足 WCAG AA，触屏和键盘能走通来源查看。
- [ ] 审核在页底可保存并下一项；批量与例外范围、引述限定语和错误保留清楚。
- [ ] 四种宽度均能操作正式组件场景，紧凑状态、人物详情职责和手机入口清楚。
