# 分阶段章节生产与可恢复的多模型复核

任务：[Issue #684](https://github.com/6spot/Loom/issues/684)。用户已确认直接实现
整章纯译文、独立提取、分步保存、有界修正和人工例外。此记录保留交付范围及
可核验标准；任务状态由现用工具管理，交付检查和合并结果由 PR 记录。

## 问题及交付范围

原联合调用要求模型同时返回完整译文和大量提取/关联信息，真实完整章试验出现
长时间等待、输出不完整、整章纠错删文以及复核忽略旧意见等问题。新流程保留
自然章的上下文，把不同职责拆成可独立保存和恢复的步骤。

唯一产品合同是
[staged-chapter-production.md](../../../apps/chronicle/docs/staged-chapter-production.md)。
模型配置、预算和恢复操作见 [worker.md](../../../apps/chronicle/docs/worker.md)，
审核 API 与交互见 [review-workflow.md](../../../apps/chronicle/docs/review-workflow.md)。
本记录不另建生产或部署流程。

```text
整章纯译文 ─┐
            ├→ 多候选比较 → 来源/时间/阶段关联 → 内容复核
原文提取 ───┘                                │
                         一次局部修正 ←───────┤
                         受影响关联 + 再复核   │
                                             ├→ 内容接受 → 既有后续生产
                                             └→ Studio 内容审核
```

单候选不调用比较。六个 AI 步骤均支持单/多模型；每次尝试和结果立即保存。
人工修订生成新版本重新复核，原样接受与修改分开。新生产使用 0.4，旧联合
0.1–0.3 保持冻结解释，不将历史试验产物假装成新步骤的结果。

## 实现边界与协作

| 部分 | 文件归属 | 验收重点 |
| --- | --- | --- |
| 0.4 合同与接受 | `persistence/staged_chapter_contract.py`、`chapter_contract.py`、`chapter_store.py`、`ingestion/schemas/*v0.4*` | 原注范围由程序固定，精确来源，完整产物与实际接受凭据绑定 |
| 阶段协议与持久执行 | `persistence/chapter_production*.py`、`worker/staged_chapter.py`、`chapter_models.py`、`model_provider.py` | 独立步骤保存、有限并发和重试、过期租约拒写、只重做受影响步骤 |
| 人工例外 | `persistence/chapter_content_review.py`、`read_api/studio_chapter_content.py` | 候选与全部意见冻结、逐项处置、原样接受/修订/驳回分开 |
| Studio | `ChapterContentReviewPanel`、导入详情和现有审核页/客户端 | 完整原文和原始候选可读、底部操作可达、草稿隔离、保存下一项 |
| 原链接线与交付 | `chapter_stage.py`、`ingestion_worker.py`、assembly/publish、Compose/Docker/CI | 复用原队列和发布事务，不绕过身份及状态审核 |

合同、审核模块及互不写入同一文件的测试可并行；共同入口、CI、依赖安装、
dist 构建和 Git 交付由协调者串行处理。本次没有引入额外队列、持久化系统、
独立发布入口或 Loom 引擎权限。

完整链路回归还发现：同一状态的开始事实会同时产生“身份”和“变化”两项，
旧编译器给两项分配同一 ID。修复以项类型区分 ID，保留身份 ID 规则与数据库
重复拒绝，编译器版本升级；没有通过放宽唯一性约束来绕过失败。

## 可执行验收标准

1. translation 与 extraction 都接收完整章，可并行；译文仅有正文，提取
   不重复正文，linking 只返回出处、实体/事件、阅读时间和阶段关联。
2. 失败的提取不重译；缺一个 reviewer 只补该 reviewer；修正失败可继续
   同一轮，修正成功后的关联失败不重新修正；最终复核失败不重做前序内容。
3. 多候选全部保存。比较必须覆盖整个候选集；不同选择或少数实质异议进入
   人工审核，即使后续 reviewer 返回 pass 也不能自动接受。
4. 请求、模型、步骤和预算按整个 job 冻结；同一本书第二章不能静默换配置。
   取消或失租停止新增调用，HTTP 总时限不被保活延长。
5. 补丁绑定目标原值，不能整章重写、删排正文或因数组移位改错对象。未变更
   的修订拒绝。复核只能核验当前稿，不能附修改同时批准。
6. 人工 A→B→A 必须形成新的审核版本；相同文字 hash 不足以复用旧决定。
   新版保留前序候选和全部意见，旧批准或修订不得再次执行。
7. 已存内容接受后发生事务失败，恢复不调用模型；章接受与 chunk run 同
   事务，发布保持全量原子性，不能产生半份公开内容。
8. 内容审核不额外制造 chunk_failure；接受前可读完整原文与所有模型原始
   返回。分页绑定冻结记录，新返回不能替换旧历史，不暴露提示词或凭据。
9. 桌面与窄屏实际浏览器验证：草稿刷新保留、不同审核项不串稿、修改后禁止
   原样接受、保存后直接下一项、修订真实落库以及操作栏可达。
10. 内容接受后仍执行跨来源身份审核与 R3 状态审核；综合历史叙事仍需显式
    选择来源并发布。本任务不增加全局自动批准规则。

## 真实质量边界

此前真实失败仍记录于 [#586](https://github.com/6spot/Loom/issues/586) 和
[试验归档 PR #681](https://github.com/6spot/Loom/pull/681)。本实现没有证明
模型已经解决所有人物指代、日期、称谓或跨来源史料问题。

新的完整章真实模型测试结果单独留证；调用完成、结构有效、内容接受、史料
质量验收和公开发布必须分别记录。本实现不关闭 #586 或父 #549，也不把
fixture 测试、模型相互一致或单章成功称为四章真实内容验收完成。
