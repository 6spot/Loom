# [C2-R2E-D01] 固定真实多史料核对案例与预期结果

## 目标

父任务：[#658](https://github.com/6spot/Loom/issues/658)（C2-R2E）。为跨史料核对和新历史正文提供可复查的输入/预期，避免后续模型自行决定什么算支持、补充或冲突。

本任务只整理真实案例与明确标注的反例，不实现生产服务，不生成待发布正文。

## 输入

- apps/chronicle/corpus/first-round/sources/ 中完整的《周瑜传》《先主传》《鲁肃传》《资治通鉴卷六十五》，含正文、注文与转引。
- 现有 chapter-production.md、data-contract.md、resolution.md、person-state-reading.md 的来源/主体/阶段规则。
- 已确认产品要求：正序连续历史正文，事件/时期只作锚点；身份确认与事实核对分开；明确性针对具体结论和适用阶段。

## 输出与文件归属

- apps/chronicle/corpus/reading-enhancement/cases.json（新）：案例清单，不定义生产 DTO。
- apps/chronicle/corpus/reading-enhancement/README.md（新）：来源索引、逐案解释与人工核对结果。
- 本任务说明。

只引用既有完整原文与 hash/selector，不复制删节成新的“完整章”；不改 provider、生产 schema、全局测试基座、页面或 dist。

## 实施步骤

1. 先核对四份原文及当前引用定位约定，记录固定 hash；材料有漂移时明确报告，不沿用旧坐标。
2. 至少整理 12 个案例，其中至少 8 个来自真实材料；缺少真实材料的机制反例标为 synthetic，真实与合成分别统计。
3. 每案包含 case_id、real/synthetic、具体核对问题、各来源/引述者、原文 selector 与 quote、主体对应是否确定、阶段及可比较性、允许结论、禁止结论、理由和可用的下游状态/导航预期。没有精确日期时保留未知。
4. 覆盖相互支持、细节补充、真正分歧、同源转引、未提到并非否定、不同阶段、兼任、同名异人/异地、相关而非同次事件、引用只支持部分结论等情形。
5. 重点可从赤壁合作记载、火攻与曹操书信的不同归因、鲁肃/周瑜决策记载及裴注、周瑜并任官职、巴丘/巴陵考订找材料。这里只是查找方向，不预先宣布每案互证或分歧结论。
6. 输出一组相邻历史片段的语义期望：锚点前后仍可连续读；主叙事阶段与旁及旧事有区别。样例仅作验收预期，不成为生产文章。
7. 逐条人工核对 quote 是否支持所写预期；同一书的篇章和转引不得直接标成多个独立证人。

## 验收

- [ ] 案例数量、真实/合成标记及覆盖项满足要求，每个真实引文可在固定来源中精确重定位。
- [ ] 核对对象是具体问题与阶段，归组不产生人物/事件同一性决定。
- [ ] “原文有这句话”和“这句话支持该结论”分别有检查结果。
- [ ] 候选推荐、当事人自述、注文考订及叙述者判断保留归属；未知不补成确定史实。
- [ ] D02 能仅凭案例索引和原文复核预期；尚未定论之处明确记录。

## 依赖、并行和验证

输入依赖第一轮已提供的完整语料（[#552](https://github.com/6spot/Loom/issues/552)），不依赖 R3 实现。D02 可先阅读既有契约并起草，但定稿须核对本任务结果；两者不改同一组文件。

执行数据格式解析、hash/selector 重定位及 Markdown 引用检查；逐案给出内容核对结果。不需要为纯语料说明运行全量生产/浏览器测试，也不能把格式检查记成真实模型验收。任务状态由当前任务管理工具维护。
